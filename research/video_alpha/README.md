# 媒体/文章 alpha 研究任务（2026-10-31 立项）

> 目标：把视频、访谈、文章、研报中的**可检验假设**筛出来，回到我们自己的原始数据做
> PIT/成本/MDE/OOS 检验；不是把观点直接变成交易信号。
> 用户原始要求：分析大量量化/股票视频或文章，找真正有价值的因子、理解行情原理，
> 提升模型收益。本文是该任务的边界、流程与验收标准。

## 1. 硬规则（先于工具）

1. **媒体是二手来源，不是证据**。视频/文章只能产生假设；结论必须由本地原始数据
   （`data_store`、QMT 快照/成交、公告原文）复算，并标 `source/as_of/口径`。
2. **不碰实盘参数**：任何候选因子在通过预登记 + IS/OOS + 成本 + MDE 前，不得进入
   `config/settings.py`、信号链或 QMT；不做"先上线再验证"。
3. **版权/ToS**：只下载公开内容用于内部研究；不转载、不再分发；优先字幕/元数据，
   避免整片批量下载；遵守平台条款。
4. **可复查**：每个来源保留 URL、发布时间、抓取时间、标题、作者、原始字幕/正文路径；
   每个结论保留脚本/命令、数据文件、样本区间、公式、累计检验数 N。
5. **已知失败方向不重复烧预算**：龙虎榜/游资、解禁、大宗、回购、减持、PEAD、
   指数调仓、高股息、CB 条款事件等已在本项目 FAIL/不部署（见 `logs/` 原始工件）；
   除非有新机制/新数据/新市场结构，否则不重复。

## 3. 流水线

1. **来源分层**
   - A：交易所/监管/公司公告/学术论文/券商研报（有数据、有方法）——优先。
   - B：有代码/数据/回测细节的从业者视频或文章——可产生假设。
   - C：纯观点/喊单/事后归因——只做情绪/叙事样本，不进因子池。
2. **抓取**：URL → 元数据 + 字幕/正文 → `data/<source_id>/`；
   记录 `fetched_at`、平台、作者、发布时间、原始链接。
3. **抽取**：每条候选写成结构化 claim：
   `claim_id, source_id, claim_text, mechanism, universe, signal_time, entry, exit,
   holding, data_needed, sample, costs, testable, status`.
4. **预登记**：写清判据、MDE、IS/OOS、只用一次 OOS、累计 N；无机制解释的"排序轴"
   不登记。
5. **复算**：本地数据/PIT/成本/涨跌停/T+1/lot；输出工件 + 脚本 + 日期。
6. **判读**：PASS/FAIL/UNDERPOWERED/NEEDS_DATA；FAIL 关闭，不再调窗口；
   PASS 也只进前向纸面，不直接实盘。

## 4. 本任务优先问题（按可检验性排序）

1. **执行/成本**：A 股 T+1、涨跌停、CB 流动性/买卖价差、10 万拆单、尾盘执行；
   这些最可能直接改善净值，且可用本地成交/盘口验证。
2. **CB 结构**：双低/低价、强赎/下修/回售、发行/上市、条款博弈；
   已关闭的条款事件不重复，找新数据/新机制。
3. **风险状态**：广度/跌停/波动聚集能否改善**波动/回撤**预测（不是方向）。
4. **跳空**：隔夜美股/A50/离岸 ETF 对开盘 gap 的预测；只改 gap，不改收盘 p。
5. **制度/资金流**：指数调仓、解禁、大宗——已测过的先读原始 FAIL 工件，不重跑。

## 5. 验收

- 每条 claim 必须能追溯到原始来源 + 本地数据 + 脚本；
- 代码改动必须有测试（`pytest tests`）；
- 研究结论必须标样本量、口径、盲区、累计 N；
- 方案必须经真实用户/真实成交验证，不以回测/仿真代替；
- 任何"收益提升"必须相对基准（CB 指数/40-60/现金）给出增量与 MDE，
  不接受只报绝对收益。
