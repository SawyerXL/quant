# 分组信号日程修复（2026-10-23 夜）

## 问题

`scripts/daily_signal_a_grouped._is_base_rebalance_day` 用的是**字面 15 日 +
自然月末最后交易日**——这是 10-19 日程统一**之前**引擎的旧口径。10-19 三原则
统一了 v2/A2/引擎/回测（`rebalance_schedule`：月中 n//2−1 + 月末倒数第二），
但**分组路径漏改**，形成第四条实现：

- 10 月：旧锚点 10-15/10-30 vs 模型 10-19/10-29；
- **11 月：11-15 是周日 → 旧实现整月没有月中锚点**，只有 11-30；
- 12 月：旧 12-15/12-31 vs 模型 12-15/12-30。

由于 9 月以来策略处于 bear/0 持仓，**尚未产生错单**；但一旦恢复持仓，live 与
100 万基准/回测不同构，且 11 月会少一次月中调仓。

## 修复

```python
from rebalance_schedule import is_rebalance_day
return is_rebalance_day(today, calendar)
```

唯一来源（闸门二十一），不再自带拷贝。

## 影响（机器值：锚点→组交易日 g0=+2 / g1=+7）

| 月份 | 旧锚点 | 旧组交易日 | 新锚点（canonical） | 新组交易日 |
|---|---|---|---|---|
| 2026-09 | 09-15 / 09-30 | 09-17/09-24、10-09/10-16 | 09-14 / 09-29 | 09-16/09-23、10-08/10-15 |
| 2026-10 | 10-15 / 10-30 | 10-19/10-26、11-03/11-10 | 10-19 / 10-29 | 10-21/10-28、11-02/11-09 |
| 2026-11 | 11-30 | 12-02/12-09 | **11-13 / 11-27** | **11-17/11-24、12-01/12-08** |
| 2026-12 | 12-15 / 12-31 | 12-17/12-24（+2027-01） | 12-15 / 12-30 | 12-17/12-24（+2027-01） |

- 当前 bear/0，**无即时交易**；下一个组调仓日按新口径（若 regime 仍 bear 则不动）。
- **11 月月中调仓恢复**（11-17/11-24）；月末组移到 12-01/12-08。

## 验证

- 全历 192 个基锚点与 `rebalance_schedule.biweekly_dates` **逐日一致**；
- `tests/test_grouped_schedule.py` 3 项：基锚点一致 / 11 月月中锚点不被吞 /
  旧 10-26 g1 不再是调仓日；
- `check_config_alignment.py` 新增"分组信号日程"检查（失败计入漂移并告警）；
- 全量测试通过。

## 残余口径（另案）

100 万基准/`three_piece` 用的是**单组合 canonical**；live 是 **{2,7} 两组**。
修完锚点后 live 与 tranching 回测（canonical+{2,7}）对齐，但与三件套的单路径
仍有 timing-luck 差异。该差异在实盘切换前需单独对齐，不在本次修复范围。

## 回滚

只改了 `_is_base_rebalance_day` 一个函数；回滚=恢复旧实现（不推荐，会重新引入
11 月缺锚点与模型不同构）。
