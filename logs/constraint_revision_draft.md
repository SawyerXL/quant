# 约束分位数修订 · 判据重锁草案（2026-10-01 起草，待用户审）

> 定位声明（用户 10-01 裁定）：本草案的落点 = **约束口径是否正确（方法学问题）**，
> 不是"修订后容量够不够扩容"。容量是结果不是目标。草案必须允许"不修订"结论。

## 一、现状口径溯源（闸门二十三，原始源）

| 约束 | 内容 | 原始依据 | 依据是否在 |
|---|---|---|---|
| 买入侧 | P95 < 3% | 09-22 流动性审计实测：60万档买入占比 P95=1.93%（ed1a430 ②"1.93% 为已知锚"）→ 3% ≈ 锚×1.55 裕度 | ✅ 有锚有裕度 |

补充事实（09-28 首跑，机器值）：单例 15% 全档不过，驱动=**单个实例**
128028@2019-11-01（当日 13 万成交额，60万档占比 18.44%）；按年份最差单例：
2019 30.73% → 2020 2.92% → 2021 5.05% → 2022~2026 全部 ≤1.7%。

## 二、问题陈述：现口径的具体缺陷（本节的成立=修订的前提）

**缺陷 1+3（同一问题的两面）：单例权重过大。** 最差单例约束被 N=1 的极端值
（2019-11 单个薄日）决定全档生死——单例无法区分"市场状态"与"策略缺陷"
（用户 09-28 原话），抽样误差最大（与 MaxDD 同族，闸门第六项）；全期一个数
同时掩盖结构性事实（2020+ 最差单例仅 5.05%，15% 线有 3 倍裕度）。

**缺陷 2：15% 定值无锚。** 溯源确认：P95<3% 有 1.93% 实测锚，15% 是"更严"的
定性手定值——与"0.5% 是未经检验的常数"（inv_vol 教训）同族：无锚定值在判据层
无法防御"阈值被挑着定"。**决定性约束（15% 杀掉 2019-11）恰好是无依据的那条。**

**判别试纸（用户 10-01）：修订理由是方法性（口径错）还是结果性（容量不够）？**
→ **方法性**：缺陷 1/2/3 都是口径构造问题，与容量无关。

## 三、候选口径集（先写死，不可追加）

## 四、判据（用户重点审）

**评估对象**：92 个月全样本的 339 个卖出实例（cb_liquidity_check 口径，含缺失
对齐修复）。三档（60/80/100万）分别算。

**每个候选口径的测量**：
1. P99 值（60/80/100万档）——09-28 已出：2.12% / 2.83% / 3.54%，全 <10%；
   修订后重算以 92 月全样本复核（10-09 数据重拉后跑）
2. 超 10% 笔数占比——09-28 已出：0.6% / 0.9% / 2.1%，需全档复核
3. 分年份 P99 序列——检查是否有年份 P99>20%（2019 预期触发"单独说明"）

**关节点：128028@2019-11 的流动性事实核查（2026-10-01 已出数，机器值）**：

```
当日成交额 13.0万 = 单日流动性谷(前后日 159.7万/722.1万, 11-04 起 722~2701万)
2019 各月中位日成交额 153~1254万, 全史中位 1635万——13万日是该券孤立异常单日
清仓天数(10% 参与率): 60万档 1.8 天 / 80万档 2.5 天 / 100万档 3.1 天
次日流动性恢复后(722万/日, 10%=72万/天) → 当日即可清出
```

**判读（用户 10-01 判据）**：1~2 天可清出（100万档 3.1 天由"次日恢复"论据
支撑）→ **现口径杀它是过度保守，修订放过它是修正而非漏洞**。"必须杀掉
128028" 的结论来自无锚的 15%——把无依据的判决继承为修订条件=循环论证，
撤回（原草案此处作废）。

**修订口径的正确性判据（独立于 15%）**：
- 有效性：三维条款共同覆盖"卖出不可跳过"的尾部风险（P99 管常规尾部 /
  超频条款管尾部频率 / 分年份条款管市场状态差异），且**不含无锚定值**，
  92 月全样本容量估计稳定
- 分年份条款**独立评估**（回答"不同市场状态下约束是否该不同"，与 128028
  单例无关，不作补救工具）：出数=逐年 P99 序列，任一年 >20% 触发单独说明
- **锚方法同族（1.93% 锚的方法抄用）**：观测尾部百分位数 → 阈值=观测×裕度。
  卖出侧观测值（60万档 P99=2.12%）× 已锁候选的裕度（10%≈4.7×）——候选集
  是写死的形式，**先算锚、再从写死候选集选最接近且不低于锚者，不新增候选
  （锚算出来 9.7% 也不能把候选改成 9.7%——那是事后调参）**

**预先锁死（用户 10-01）**：①全样本重算容量，不只看近期 ②容量变大不构成扩容
理由 ③"现口径正确"是合法结论 ④候选集不可事后追加。

## 五、结论的三种可能及处置

| 结论 | 条件 | 处置 |
|---|---|---|
| A. 现口径正确 | 修订口径在有效性判定上劣于现口径 | **结案记录，扩容保持关闭** |
| B. 修订口径正确 | 有效性判定全过（三维覆盖+无锚定值+全样本稳定） | 采用修订口径 + 92 月全样本容量重算（出数=三档容量上限） |
| C. 修订仍不足 | 分年份条款暴露多年度系统性问题（超出单一年份单独说明可容纳的范围） | 维持现口径 + 记录盲区（单例绑架为已知缺陷） |

## 六、与扩容的关系（声明）

- 本修订是方法学事项，**落点=口径正确性，容量是副产品**
- **容量变大不自动触发扩容**；扩容重开条件（09-28 用户裁定）= 受控实验完成 +
  约束修订 + 三档全过 + 带新判据——即使全满足，扩容仍须独立判据另行立项
  （执行成本实测/冲击/换手），本草案不提供
- 若结论 B 且容量重算显示上限高于 60 万 → 记录为"容量上限"数字，供未来独立
  立项引用，不构成行动
