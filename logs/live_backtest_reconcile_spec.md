# live-vs-backtest 对账规格（2026-09-13 深夜定，实现周二后）

**动机**：快照断三天无人发现——"实盘持仓 vs 回测应有持仓"的逐日 diff
链路目前不存在。这是最快发现"回测和实盘不是同一个策略"的机制，而
那类错误比任何统计问题都致命。

## 规格

**每日（盘后，持仓快照可得后）**：
```
输入:  实盘持仓快照(logs/qmt_positions_latest.json)
       回测同参数同信号日期链的应有持仓(引擎 + 实盘信号记录回放)
输出:  三路 diff
       ① 名单 diff:   实盘有/应有无、应有有/实盘无
       ② 权重 diff:   逐票 |w_live − w_model|
       ③ 现金档 diff: 实盘总仓位 vs 模型档位仓位
```

**阈值与处置**：
```
名单 diff > 2 只 或 任一票权重 diff > 5pp 或 现金档差 > 1 档
→ 记录事件 → 归因四选一:
   (a) 未成交/部分成交(查当日执行记录)
   (b) 停牌/涨跌停无法交易
   (c) 参数漂移(引擎/实盘配置不一致 → 触发 check_config_alignment)
   (d) 实现 bug(其余)
归因 (d) 或无归因 → P0
```

**口径差归因（2026-09-16 加，分红缺失实锤后）**：实盘收益天然含分红
（全收益口径），回测为价格口径——对账的收益 diff 中存在 **~2pp/年
系统性口径差**，必须预先扣除后再判偏差；未扣除时的"实盘跑赢回测"
=口径伪影，不构成结论。

**数据依赖**：实盘持仓快照是唯一瓶颈（隧道链，周一判据(b)）；快照
缺失当日标记"对账不可行"，并计入快照健康（健康行 snapshot 字段）。
